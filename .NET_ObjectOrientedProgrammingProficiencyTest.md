## Pregunta 01
### Una variable local:
- ❌ Puede ser utilizada en cualquier parte del programa
- ✅ Es declarada dentro de un método
- ❌ Tiene que aceptar una clase
- ❌ Representa un objeto

**Explicación:**
Una variable local es aquella que se declara dentro de un método y solo existe en el scope (alcance) de ese método. Su vida comienza cuando se declara y termina cuando el método finaliza.

**Características:**
- Solo accesible dentro del método donde se declara
- Se crea cada vez que el método es llamado
- Se destruye cuando el método termina
- No tiene valor por defecto (debe inicializarse)

```csharp
public class VariablesLocales
{
    public void Ejemplo()
    {
        // Variable local - solo existe dentro de este método
        int edad = 25;
        string nombre = "Juan";
        
        Console.WriteLine($"Nombre: {nombre}, Edad: {edad}");
    }
    
    public void OtroMetodo()
    {
        // Aquí NO se puede acceder a 'edad' ni 'nombre'
        // Console.WriteLine(edad); // ERROR: no existe en este scope
    }
}

// Comparación con variable de clase:
public class Vehiculo
{
    private string marca; // Variable de instancia (accesible en toda la clase)
    
    public void Acelerar()
    {
        int velocidad = 100; // Variable local (solo en este método)
        marca = "Toyota";    // Acceso a variable de instancia
    }
}
```

## Pregunta 02
### Definir 2 métodos con el mismo nombre, pero con diferentes parámetros es llamado:
- ❌ Loading
- ✅ Overloading
- ❌ Multiplexing
- ❌ Duplexing

**Explicación:**
Overloading (sobrecarga) es un concepto de programación orientada a objetos que permite definir múltiples métodos con el mismo nombre, siempre que tengan diferentes parámetros. Esto mejora la legibilidad y usabilidad del código.

**Formas de diferenciarse:**
- Diferente número de parámetros
- Diferente tipo de parámetros
- Diferente orden de parámetros

```csharp
public class Calculadora
{
    // Overloading - mismo nombre, diferentes parámetros
    
    // Versión 1: dos int
    public int Sumar(int a, int b)
    {
        return a + b;
    }
    
    // Versión 2: tres int
    public int Sumar(int a, int b, int c)
    {
        return a + b + c;
    }
    
    // Versión 3: dos double
    public double Sumar(double a, double b)
    {
        return a + b;
    }
    
    // Versión 4: diferentes tipos
    public void Imprimir(string mensaje)
    {
        Console.WriteLine(mensaje);
    }
    
    public void Imprimir(int numero)
    {
        Console.WriteLine(numero);
    }
    
    public void Imprimir(double numero)
    {
        Console.WriteLine(numero);
    }
}

// Uso:
var calc = new Calculadora();
Console.WriteLine(calc.Sumar(5, 3));              // Versión 1: 8
Console.WriteLine(calc.Sumar(5, 3, 2));          // Versión 2: 10
Console.WriteLine(calc.Sumar(5.5, 3.2));         // Versión 3: 8.7

calc.Imprimir("Hola");                           // Versión 1: Hola
calc.Imprimir(42);                               // Versión 2: 42
calc.Imprimir(3.14);                             // Versión 3: 3.14
```

## Pregunta 03
### El polimorfismo ocurre cuando los métodos de la clase hija:
- ❌ Sobrescriben los métodos de la clase padre, pero mantienen la implementación
- ✅ Mantienen el mismo valor de retorno y los argumentos que la clase padre, pero se implementan de forma diferente
- ❌ Tienen diferente valores de retorno y argumentos que la clase padre
- ❌ Son virtuales

**Explicación:**
Polimorfismo (muchas formas) es la capacidad de una clase derivada de sobrescribir (override) métodos de la clase padre. Los métodos mantienen la misma firma (nombre, parámetros, retorno) pero implementan comportamiento diferente.

**Requisitos para polimorfismo:**
- Debe existir herencia (clase padre y clase hija)
- La clase padre debe tener un método virtual
- La clase hija sobrescribe ese método con `override`
- Misma firma de método
- Implementación diferente

```csharp
// Clase padre
public class Animal
{
    // Método virtual permite ser sobrescrito
    public virtual void Hacer Sonido()
    {
        Console.WriteLine("Sonido genérico");
    }
}

// Clases hijas - polimorfismo
public class Perro : Animal
{
    public override void HacerSonido()
    {
        Console.WriteLine("¡Guau guau!");
    }
}

public class Gato : Animal
{
    public override void HacerSonido()
    {
        Console.WriteLine("¡Miau!");
    }
}

public class Pajaro : Animal
{
    public override void HacerSonido()
    {
        Console.WriteLine("¡Pío pío!");
    }
}

// Uso del polimorfismo
public class Programa
{
    public static void Main()
    {
        // Polimorfismo: una variable de tipo Animal puede referenciar a cualquier clase hija
        Animal animal1 = new Perro();
        Animal animal2 = new Gato();
        Animal animal3 = new Pajaro();
        
        animal1.HacerSonido(); // Output: ¡Guau guau!
        animal2.HacerSonido(); // Output: ¡Miau!
        animal3.HacerSonido(); // Output: ¡Pío pío!
        
        // También funciona en colecciones
        List<Animal> animales = new List<Animal> 
        { 
            new Perro(), 
            new Gato(), 
            new Pajaro() 
        };
        
        foreach (var animal in animales)
        {
            animal.HacerSonido(); // Cada uno hace su propio sonido
        }
    }
}
```

## Pregunta 04
### Si un atributo es privado. ¿Cuáles métodos tienen acceso a él?
- ✅ Solamente aquellos definidos en la misma clase
- ❌ Solamente los métodos estáticos en la misma clase
- ❌ Solamente métodos de instancias en la misma clase
- ❌ Solamente clases del mismo namespace

**Explicación:**
Los atributos privados (`private`) solo son accesibles dentro de la misma clase. No importa si el método es estático o de instancia, ambos pueden acceder a atributos privados de la clase.

**Niveles de acceso en C#:**
- `private` - Solo dentro de la clase
- `protected` - Dentro de la clase y clases derivadas
- `public` - Accesible desde cualquier lugar
- `internal` - Dentro del mismo assembly

```csharp
public class Persona
{
    // Atributo privado
    private string numeroIdentidad;
    private int edad;
    
    // Método de instancia - SÍ puede acceder a privado
    public void AsignarIdentidad(string id)
    {
        numeroIdentidad = id; // ✅ Funciona
    }
    
    // Método de instancia - SÍ puede acceder
    public string ObtenerIdentidad()
    {
        return numeroIdentidad; // ✅ Funciona
    }
    
    // Método estático - SÍ puede acceder a atributos privados
    public static void VerificarEdad(Persona p)
    {
        // Aquí accedemos a través de una instancia
        // p.edad = 30; // ✅ Funciona
    }
    
    // Constructor - SÍ puede acceder (es parte de la clase)
    public Persona(string id, int e)
    {
        numeroIdentidad = id;  // ✅ Funciona
        edad = e;              // ✅ Funciona
    }
}

public class Otra Clase
{
    public void ProbarAcceso()
    {
        var persona = new Persona("123456", 30);
        
        // Esto NO funciona - numeroIdentidad es privado
        // string id = persona.numeroIdentidad; // ❌ ERROR
        
        // Debe usar métodos públicos
        persona.AsignarIdentidad("789");         // ✅ Correcto
    }
}
```

## Pregunta 05
### El concepto de clase derivada está relacionado con:
- ❌ Encapsulamiento
- ❌ Ocultación de datos
- ❌ Tipo de datos abstractos
- ✅ Herencia

**Explicación:**
Una clase derivada (también llamada clase hija o subclase) es una clase que hereda de otra clase (clase padre o superclase). La herencia es el mecanismo mediante el cual una clase obtiene propiedades y métodos de otra clase.

**Terminología:**
- Clase base / Clase padre / Superclase = la que se hereda
- Clase derivada / Clase hija / Subclase = la que hereda

```csharp
// Clase base (padre)
public class Vehiculo
{
    public string Marca { get; set; }
    public string Modelo { get; set; }
    
    public virtual void Arrancar()
    {
        Console.WriteLine("Vehículo arrancando...");
    }
}

// Clase derivada (hija) - hereda de Vehiculo
public class Coche : Vehiculo
{
    public int NumeroPuertas { get; set; }
    
    public override void Arrancar()
    {
        Console.WriteLine("Coche arrancando con motor de 4 cilindros...");
    }
}

// Otra clase derivada
public class Motocicleta : Vehiculo
{
    public bool TieneSidecar { get; set; }
    
    public override void Arrancar()
    {
        Console.WriteLine("Motocicleta arrancando...");
    }
}

// Uso:
var coche = new Coche { Marca = "Toyota", Modelo = "Corolla" };
var moto = new Motocicleta { Marca = "Harley", Modelo = "Street 750" };

coche.Arrancar();  // Coche arrancando con motor de 4 cilindros...
moto.Arrancar();   // Motocicleta arrancando...
```

## Pregunta 06
### La herencia es un modo de:
- ❌ Organizar los datos
- ❌ Pasar argumentos a los objetos de la clase
- ✅ Agregar features a las clases existentes sin tener que reescribirlas
- ❌ Mejorar la encapsulación

**Explicación:**
La herencia permite reutilizar código. Una clase derivada hereda todos los miembros (atributos y métodos) de la clase base, evitando duplicación de código y promoviendo la reutilización.

**Ventajas de la herencia:**
- Reutilización de código
- Jerarquía de clases lógica
- Polimorfismo
- Mantenimiento más fácil
- Eliminación de duplicación

```csharp
// Clase base con features comunes
public class Empleado
{
    public string Nombre { get; set; }
    public double Salario { get; set; }
    
    public virtual void MostrarInfo()
    {
        Console.WriteLine($"Nombre: {Nombre}, Salario: {Salario}");
    }
    
    public void CalcularBonus()
    {
        Console.WriteLine($"Bonus: {Salario * 0.1}");
    }
}

// Clase derivada - hereda todo de Empleado y agrega nuevas features
public class Gerente : Empleado
{
    public int NumeroEmpleadosACargo { get; set; }
    
    public void AsignarTareas()
    {
        Console.WriteLine($"{Nombre} asigna tareas a {NumeroEmpleadosACargo} empleados");
    }
    
    public override void MostrarInfo()
    {
        base.MostrarInfo();
        Console.WriteLine($"Supervisa: {NumeroEmpleadosACargo} empleados");
    }
}

// Uso:
var gerente = new Gerente 
{ 
    Nombre = "Carlos", 
    Salario = 5000,
    NumeroEmpleadosACargo = 10 
};

gerente.MostrarInfo();     // Hereda y extiende
gerente.CalcularBonus();   // Hereda de Empleado
gerente.AsignarTareas();   // Feature nueva
```

## Pregunta 07
### ¿Qué concepto permite que los detalles que contiene una clase, no estén visibles para otras clases y objetos que lo usan?
- ✅ Encapsulamiento
- ❌ Herencia
- ❌ Polimorfismo
- ❌ Abstracción

**Explicación:**
Encapsulamiento es el mecanismo de ocultar los detalles internos de una clase y exponer solo lo necesario a través de una interfaz pública. Se logra mediante modificadores de acceso como `private`, `protected` y `public`.

**Principio de encapsulamiento:**
- Atributos `private` - datos internos ocultos
- Métodos `public` - interfaz controlada hacia el exterior
- Propiedades - acceso controlado a los datos

```csharp
// Ejemplo SIN encapsulamiento (MALO)
public class CuentaBancaria_Mal
{
    public double Saldo;  // ❌ Público - vulnerable
    
    public void Depositar(double monto)
    {
        Saldo += monto;
    }
    
    public void Retirar(double monto)
    {
        if (monto <= Saldo)
            Saldo -= monto;
    }
}

// Alguien podría hacer:
// cuenta.Saldo = -999999;  // ❌ Corrupción de datos

---

// Ejemplo CON encapsulamiento (BIEN)
public class CuentaBancaria_Bien
{
    private double saldo;  // ✅ Privado - protegido
    private string numeroCuenta;
    private List<string> historial;
    
    public CuentaBancaria_Bien(string numero, double saldoInicial)
    {
        numeroCuenta = numero;
        saldo = saldoInicial;
        historial = new List<string>();
    }
    
    // Propiedad para acceso controlado
    public double Saldo
    {
        get { return saldo; }
        private set { saldo = value; } // Solo esta clase puede modificar
    }
    
    public string NumeroCuenta
    {
        get { return numeroCuenta; }
    }
    
    public void Depositar(double monto)
    {
        if (monto > 0)
        {
            Saldo += monto;
            historial.Add($"Depósito: +{monto}");
        }
    }
    
    public bool Retirar(double monto)
    {
        if (monto > 0 && monto <= Saldo)
        {
            Saldo -= monto;
            historial.Add($"Retiro: -{monto}");
            return true;
        }
        return false;
    }
    
    public void MostrarHistorial()
    {
        foreach (var transaccion in historial)
            Console.WriteLine(transaccion);
    }
}

// Uso seguro:
var cuenta = new CuentaBancaria_Bien("12345", 1000);
cuenta.Depositar(500);          // ✅ Funciona
Console.WriteLine(cuenta.Saldo); // ✅ Lectura segura
// cuenta.Saldo = -999;          // ❌ ERROR - no se puede hacer
```

## Pregunta 08
### ¿Cuál de los siguientes, permite extraer solamente la información necesaria de un objeto de forma de no mostrar todos los detalles técnicos del objeto?
- ❌ Encapsulamiento
- ❌ Herencia
- ✅ Abstracción
- ❌ Polimorfismo

**Explicación:**
Abstracción es el proceso de ocultar la complejidad y mostrar solo las características esenciales de un objeto. Permite trabajar con objetos a un nivel más alto, sin preocuparse por los detalles de implementación.

**Diferencia entre Encapsulamiento y Abstracción:**
- **Encapsulamiento**: CÓMO ocultar los datos (modificadores de acceso)
- **Abstracción**: QUÉ mostrar y QUÉ ocultar (concepto lógico)

```csharp
// Ejemplo: Sistema de Vehículos

// Abstracción - interfaz simplificada
public abstract class Vehiculo
{
    // Detalles técnicos complejos - OCULTOS
    private Engine motor;
    private Transmision transmision;
    private SistemaElectrico sistemaElectrico;
    private SistemaFreno sistemaFreno;
    
    // Lo ESENCIAL - VISIBLE
    public string Marca { get; set; }
    public string Modelo { get; set; }
    
    public abstract void Arrancar();
    public abstract void Acelerar();
    public abstract void Frenar();
    public abstract void Apagar();
}

// Implementación específica
public class Coche : Vehiculo
{
    public override void Arrancar()
    {
        // Detalles técnicos complejos aquí
        Console.WriteLine("Sistema eléctrico activado...");
        Console.WriteLine("Inyectores de combustible iniciados...");
        Console.WriteLine("¡Coche encendido!");
    }
    
    public override void Acelerar()
    {
        Console.WriteLine("Coche acelerando...");
    }
    
    public override void Frenar()
    {
        Console.WriteLine("Frenos activados...");
    }
    
    public override void Apagar()
    {
        Console.WriteLine("Coche apagado");
    }
}

// Uso - Usuario solo ve lo esencial
public class Programa
{
    public static void Main()
    {
        Vehiculo coche = new Coche 
        { 
            Marca = "Toyota", 
            Modelo = "Camry" 
        };
        
        coche.Arrancar();  // ✅ Usuario no necesita conocer todos los detalles internos
        coche.Acelerar();
        coche.Frenar();
        coche.Apagar();
        
        // El usuario NO necesita saber:
        // - Cómo funciona el motor internamente
        // - Tipos de inyectores
        // - Voltaje del sistema eléctrico
        // Solo sabe: Arrancar, Acelerar, Frenar, Apagar
    }
}

// Otro ejemplo: Cajero Automático
public abstract class CajeroAutomatico
{
    // Detalles complejos OCULTOS
    private DatabaseConexion bd;
    private CriptografiaSistema cripto;
    private LogTransacciones log;
    private SistemaSeguridad seguridad;
    
    // Interfaz SIMPLE para el usuario
    public abstract void InsertarTarjeta();
    public abstract void IngresarPin();
    public abstract void RetirarDinero(double monto);
    public abstract void VerSaldo();
    public abstract void RetirarTarjeta();
}

// El usuario ve una interfaz simple, pero internamente es muy complejo
```

## Resumen de los 4 Pilares de OOP

| Concepto | Propósito |
|----------|-----------|
| **Encapsulamiento** | Ocultar detalles con `private`, `public`, etc. |
| **Herencia** | Reutilizar código mediante clases derivadas |
| **Polimorfismo** | Permitir diferentes comportamientos con la misma interfaz |
| **Abstracción** | Simplificar mostrando solo lo esencial |
