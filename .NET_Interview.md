## Fundamentos y Lógica

### 1. Diferencias entre `int`, `var` y `dynamic`
```csharp
int numero = 10;         // Tipo fijo, compilación
var texto = "Hola";      // Inferido en compilación, no cambia
dynamic algo = 10;       // Se evalúa en ejecución, puede cambiar de tipo
```

### 2. FizzBuzz del 1 al 100
```csharp
for (int i = 1; i <= 100; i++)
{
    if (i % 15 == 0) Console.WriteLine("FizzBuzz");
    else if (i % 3 == 0) Console.WriteLine("Fizz");
    else if (i % 5 == 0) Console.WriteLine("Buzz");
    else Console.WriteLine(i);
}
```

### 3. Operador `??` (null-coalescing)
```csharp
string nombre = null;
string resultado = nombre ?? "Invitado"; // "Invitado"
```

### 4. Ordenar números sin `.Sort()` (descendente)
```csharp
int[] numeros = { 5, 2, 9, 1, 7 };
for (int i = 0; i < numeros.Length - 1; i++)
{
    for (int j = 0; j < numeros.Length - 1 - i; j++)
    {
        if (numeros[j] < numeros[j + 1])
        {
            int temp = numeros[j];
            numeros[j] = numeros[j + 1];
            numeros[j + 1] = temp;
        }
    }
}
```

### 5. Ordenar textos alfabéticamente sin `.Sort()`
```csharp
string[] nombres = { "Carlos", "Ana", "Luis", "Bea" };
for (int i = 0; i < nombres.Length - 1; i++)
{
    for (int j = 0; j < nombres.Length - 1 - i; j++)
    {
        if (nombres[j].CompareTo(nombres[j + 1]) > 0)
        {
            string temp = nombres[j];
            nombres[j] = nombres[j + 1];
            nombres[j + 1] = temp;
        }
    }
}
```

## Programación Orientada a Objetos (POO)

### 1. Pilares de la POO
- Encapsulamiento: Oculta detalles internos. Acceso mediante propiedades (get/set).
- Herencia: Una clase puede heredar de otra: class Perro : Animal.
- Polimorfismo:
    - Sobrecarga: Mismo nombre, distintos parámetros.
    - Sobrescritura: Clase hija redefine métodos de la clase padre con override.
- Abstracción: Se expone solo lo esencial. Usando abstract o interface.

### 2. Ejercicio: Herencia y polimorfismo
```csharp
public class Animal
{
    public virtual void HacerSonido() { }
}

public class Perro : Animal
{
    public override void HacerSonido() => Console.WriteLine("Guau");
}

public class Gato : Animal
{
    public override void HacerSonido() => Console.WriteLine("Miau");
}
```
```csharp
List<Animal> animales = new List<Animal> { new Perro(), new Gato() };
foreach (var animal in animales) animal.HacerSonido();
```

### 3. Diferencia entre `==` y `.Equals()`
```csharp
string a = "hola";
string b = "hola";

Console.WriteLine(a == b);       // True (valores)
Console.WriteLine(a.Equals(b));  // True (contenido)
```

### 4. Interface vs Clase Abstracta
| Característica        | Interface                      | Clase Abstracta               |
| --------------------- | ------------------------------ | ----------------------------- |
| Instanciable          | ❌ No                           | ❌ No                          |
| Implementación lógica | ✅ (desde C# 8.0) con `default` | ✅ Sí                          |
| Herencia múltiple     | ✅ Sí                           | ❌ No                          |
| Propósito             | Contrato                       | Base común con lógica parcial |

### 5. Ejercicio: Clase `Empleado`
```csharp
public class Empleado
{
    public string Nombre { get; set; }
    public int SueldoBase { get; set; }
    public int HorasExtras { get; set; }

Console.WriteLine($"Sueldo total de {empleado.Nombre}: {empleado.CalcularSueldoTotal()}");
```

## APIs y Arquitectura Web
### 1. Principios fundamentales del diseño de una API REST
#### Los principios clave del diseño REST (Representational State Transfer) son:
- **Uniformidad de la interfaz:** Todos los recursos se acceden mediante URLs claras y un conjunto fijo de métodos HTTP (GET, POST, PUT, DELETE). Esto permite que los clientes interactúen de manera predecible.

- **Separación cliente-servidor:** El cliente y el servidor se desarrollan y despliegan de forma independiente, lo que mejora la escalabilidad y la flexibilidad.

- **Sin estado (stateless):** Cada solicitud debe contener toda la información necesaria, lo que permite escalar horizontalmente sin mantener sesiones en el servidor.

- **Caché:** Las respuestas deben incluir información sobre si pueden ser almacenadas en caché, mejorando así el rendimiento.

- **Sistema en capas:** Una arquitectura REST puede estar compuesta por múltiples capas (como gateways, balanceadores, proxies), lo que facilita el mantenimiento y la evolución del sistema.

- **Código bajo demanda (opcional):** El servidor puede enviar código ejecutable al cliente, como scripts JavaScript.

#### ¿Cómo aseguran la escalabilidad y mantenibilidad?
- **Escalabilidad:** Al ser sin estado, las APIs REST pueden manejar múltiples solicitudes simultáneas distribuidas en diferentes servidores.

- **Mantenibilidad:** La interfaz uniforme y la separación de responsabilidades hacen que el código sea más fácil de mantener y evolucionar sin afectar a los clientes.

### 2. Inyección de Dependencias (DI) y Tiempo de vida Scoped, Transient y Singleton
- **La Inyección de Dependencias** (DI) es un patrón de diseño utilizado para implementar la Inversión de Control (IoC). Permite gestionar desde el contenedor de dependencias los servicios que una clase necesita, promoviendo un código más limpio y desacoplado.
```csharp
public class Startup
{
    public void ConfigureServices(IServiceCollection services)
    {
        // Registrar servicios
        services.AddScoped<IMyService, MyService>();
        services.AddTransient<IOtherService, OtherService>();
        services.AddSingleton<IThirdService, ThirdService>();
    }
}
```
| **Tiempo de vida** | **Creación de la instancia**                           | **Alcance**                                  | **Caso de uso**                                                                                       |
| ------------------ | ------------------------------------------------------ | -------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **Scoped**         | Se crea una vez por **solicitud HTTP**.                | Misma instancia durante toda la solicitud    | Servicios que deben compartir datos dentro de una misma solicitud, como `DbContext` en EF Core.       |
| **Transient**      | Se crea cada vez que se inyecta.                       | Instancia diferente cada vez.                | Servicios ligeros, sin estado y que no requieren compartir datos (por ejemplo, validaciones simples). |
| **Singleton**      | Se crea una sola vez durante la vida de la aplicación. | Misma instancia compartida entre solicitudes | Servicios globales, como loggers, proveedores de configuración o almacenamiento en caché.             |

> [!IMPORTANT]
>  **Nota:** Con Scoped, todas las operaciones dentro de una misma solicitud HTTP (como múltiples llamadas internas al servicio) usan la misma instancia. En cambio, Transient genera una nueva instancia para cada inyección, incluso dentro de la misma solicitud.
